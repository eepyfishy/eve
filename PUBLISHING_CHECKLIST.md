# Documentation and release review

The repository is public and uses the [MIT License](LICENSE). Apply these checks
when updating documentation or preparing a future release:

- Distinguish planned features from behavior verified at an exact revision.
- Keep credentials, personal memories, private endpoints, and keys out of files and git history.
- Use sanitized screenshots, recordings, and sample inputs.
- Label demonstrations with the software revision, manual steps, and simulated behavior.
- Verify repository links and setup commands against the version being described.
- Add installation instructions only with a reproducible eve build.
- Establish a private disclosure channel before inviting vulnerability reports; see [security and trust](docs/security.md).
