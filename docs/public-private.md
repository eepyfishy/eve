# Public edition and private development

The public eve project explains and may eventually distribute a reusable assistant experience built on eef. It is not intended to publish any person's private assistant instance.

## Appropriate for the public repository

- High-level product purpose and architecture.
- Generalized feature specifications.
- Reproducible demos with sanitized sample data.
- Public APIs and testable examples.
- Open issues and contributions that do not reveal sensitive information.

## Keep out of this repository

- Private memory, conversation archives, or personalized assistant context.
- API keys, credentials, tokens, certificates, private keys, or actual secrets in examples.
- Private device inventory, addresses, firewall rules, authentication setup, or trust relationships.
- Private automation, integrations, experimental models, or design details not selected for public release.
- Personal images, recordings, documents, and logs.

## Publishing rules

1. Write documentation for the **public edition**, not as a diary of private development.
2. Prefer fictional example users, devices, and addresses.
3. Remove metadata and sensitive logs from screenshots and recordings.
4. Clearly distinguish implemented, prototyped, and proposed features.
5. Review commits and git history for secrets before publishing. Removing a secret from the latest file does not remove it from previous commits.

The public and private editions may evolve differently. Documentation should not imply feature parity or promise release of private capabilities.
